## Purpose (source-of-truth model)
Third-party Linux admin (`ip`, `ifconfig`, shell scripts) must not mutate kernel network state directly. Netbroker **short-circuits** the kernel RTNL/ioctl/socket path, forwards the original request to **nbproxy** via genl, and nbproxy updates the **NXOS control plane** (urib, netstack, vsh, …). The kernel is then updated either by **replaying** the RTNL through the broker's registered socket (`LIBNB_CFG_OK`) or by **NXOS daemons** on the whitelist (`LIBNB_CFG_OK_PROCESSED`).

## LIVE flow: third-party `ip route add` (RTNL example)
1. User process sends `RTM_NEWROUTE` on `NETLINK_ROUTE`.
2. `rtnetlink_rcv_msg` -> `netbroker_rtnl_doit` -> `cisco_nb_rtnl_doit`.
3. **Bypass gates** (any match -> `NETBROKER_CONTINUE`, kernel processes normally):
   - [branch] `disable_rtnl_hook` module param set
   - [branch] `cisco_nb_allow_by_current()` whitelist (comm names: `ipfib`, `kim`, `netstack:`, `urib`, `u6rib`, `ifmgr`, …; Smack `vmo`; LC LXC cgroup; non-init user_ns + `CAP_NET_ADMIN`)
   - [branch] `get_grp_map` returns `NB_GRP_NONE` (unmapped family/type)
   - [branch] no broker registered for group
   - [branch] sender `NETLINK_CB(skb).portid == ne->rtnl_pid` (broker replay path)
   - [branch] `check_interface_change` returns continue-only (e.g. NEWLINK size probe)
4. **Trap path** (broker registered, sender not whitelisted):
   - `get_grp_map` classifies route (dynamic vs `NB_GRP_STATIC_ROUTE` via fib lookup on DELROUTE with unspecified protocol)
   - [branch] `cisco_nb_block_change(grp)` -> `-EOPNOTSUPP`
   - [branch] interface forbidden attrs (IFLA_IFNAME/ADDRESS on NEWLINK/SETLINK) -> `-EOPNOTSUPP`
   - `nb_send_request(ne, subgrp, NB_API_RTNL, cloned skb, nb_rtnl_resp_cb, ...)`
   - return `NETBROKER_HANDLED`, `*rc = -EINTR` (kernel RTNL path aborted; no premature ACK)
5. **Userspace** (`request_msg_handler` in `libnb-msgs.c`):
   - parse genl + `NB_A_ORIG_MSG` (original RTNL bytes)
   - encode -> `libnb_cfg_data` via group parser (`rib_encode`, `intfc_encode`, …)
   - `cfg_cb` (e.g. `urib_cfg_req`): `nb_add_route` / `nb_del_route` -> urib APIs
6. **Completion semantics** (`libnetbroker.h`):
   - [branch] `LIBNB_CFG_OK_PROCESSED`: NXOS owns kernel programming; `libnb_ack(PROCESSED)` only; ipfib/netstack programs kernel later via whitelist
   - [branch] `LIBNB_CFG_OK`: broker may call `libnb_update_kernel` -> replays stored RTNL on `nb->rtnl_sk`; hook sees matching `rtnl_pid` -> pass-through
7. `libnb_ack` -> genl `NB_C_REQUEST` response -> `nb_rcv_request` -> `nb_rtnl_resp_cb` -> `netlink_ack` to original user socket.

## Parallel hook surfaces (same broker pattern)
- **Legacy ioctl**: `dev_ioctl` -> `netbroker_dev_ioctl` -> `cisco_nb_dev_ioctl` (`cisco_nb_ioctl.c`); used by `ifconfig`-style tools.
- **Socket ioctl**: `sock_ioctl` / `compat_sock_ioctl` -> `cisco_nb_sock_ioctl`.
- **Socket bind/connect/release**: separate kernel patches -> `cisco_nb_sock.c` handlers -> `NB_GRP_SOCKET`.
